# Job Agent v3：公开岗位搜索与自动筛选

## 范围与验收

复用 PlatformRuntime、JobRuntime、三个 Skill、简历加载、local/llm、证据检查、评分和 JobMemory。新增搜索层不成为模型工具，模型不能根据网页指令访问其他链接、登录或提交申请。

验收：离线样例完成搜索结果导入 → 过滤 → 去重 → 三 Skill → 评分 → 保存 → 优先列表；同岗位跨来源/跨进程复用报告；换简历或实质改变 JD 重新分析；搜索不调用 LLM；未分析和未知条件不伪造匹配分；robots、验证码、超时、重定向与请求边界通过 mock 验证。

## 结构

```text
main.py --agent job
  └─ cli.py（保留 v2，分发搜索参数）
      └─ search_cli.py（离线样例 / 公开来源）
          ├─ search.py
          │   ├─ PublicFetcher：公开 HTTPS GET、robots、限速与请求边界
          │   ├─ html：列表页相关链接 + JobPosting JSON-LD / 明确标签详情
          │   └─ greenhouse：官方公开 Job Board GET，带正文
          ├─ city_policy.py（正文地点、阶段阈值与城市分组）
          └─ discovery.py
              ├─ 本地方向、类型、届别、学历、截止日期和 JD 质量过滤
              ├─ DiscoveryStore：原 jobs.sqlite 内两张新增表
              ├─ JobRuntime.analyze(..., selected="all")（原 v2）
              └─ 可解释排序、来源、链接、证据和本地 JSON 完整报告
```

岗位保留公司、标题、城市、招聘类型、JD、原文/摘要标签、来源、原始链接、发现时间和可选截止日期。城市/类型/届别缺失标未知，未知公司和仅有标题的结果不进入分析。JD 沿用 v2 的 NFKC 规范化，不生成模型摘要，保留原始链接供核对。

## 公开来源与边界

城市顺序为广州、上海、深圳；优先公司官方广州岗位页及广州高校公开就业网。原验收验证过部分高校页面，新城市流程尚未真实验证。来源 URL、无需登录访问与网站规则需再次确认后启用。本轮不进行真实网络搜索。

通用 HTML 适配只读静态内容：JobPosting JSON-LD 或明确的公司/岗位/地点/任职要求标签。从配置列表页最多跟进3个同域目标方向链接，不运行网页 JS。JS 空壳或无完整字段直接标记需人工核验。

Greenhouse 公开接口补充使用该系统的企业。官方文档说明岗位 GET 无需鉴权：[Job Board API](https://docs.greenhouse.io/job-board.html)。只读列表与 JD，不使用申请 POST。字段参考 [JobPosting](https://schema.org/JobPosting)。已核验 [Lever 文档](https://github.com/lever/postings-api)，但本版未增加 Lever 适配。

不访问账号、密码、Cookie，不向搜索来源发送简历，不绕过登录、验证码或 robots。不伪装浏览器、不重试、不跟随 HTTP 重定向；受限页面可继续使用手动导入。

每轮最多3个启用来源、每来源4页、24个HTTP请求（含robots）、每响应1MB、15秒请求超时。默认间隔1秒，遵守可解析crawl-delay和request-rate（所需间隔大于5秒本轮跳过）。候选默认8个、最多20个；新分析默认2个、最多5个。地址限配置域名、HTTPS标准端口与公开DNS，禁止本地/内部地址；来源须由用户核验，不能让岗位内容扩大访问范围。

现有 Codex 网页搜索和浏览器可在确认后辅助核验来源；它们不是 Python 可自动调用的免费搜索服务。本轮无安装、无新增账号/API Key/Plugin/MCP/Skill。来源模板全部禁用。本版本搜索范围是已配置来源，不承诺全网覆盖。

## 去重、复用与费用

原 SQLite 新增 `discovered_jobs`（规范岗位及多来源别名）和 `discovery_analyses`（背景/模式对应的执行状态与报告）。原岗位、报告与LLM提取缓存继续使用。

同公司、同标题、同城市、同招聘类型：规范JD相同合并；长JD在要求签名完全一致、文本相似度≥0.94时合并。签名保留技能、要求段、学历、届别、数值和否定；短摘要或实质条件变化不近似合并，C++/C#等符号保留。重复来源追加链接与发现时间。

缓存按规范岗位、简历指纹、模式、模型、schema、本地规则和评分版本区分。成功报告直接复用；local不能冒充llm；换背景重新匹配。JD已带一致公司/岗位头时保留原输入，复用v2已有岗位哈希与同背景完整报告。开始分析前持久登记：异常、中断或拒绝后不在搜索中静默重试，可用v2单份入口人工核对。LLM失败fallback明确记录local，并在下轮复用该结果。

搜索不调用模型。local费用0；llm沿用逐份材料确认、无重试、每进程最多6请求/约1元保守预算边界。默认2岗位最多6请求；按既有配置每岗位三轮保守估算约0.45432元，两岗约0.90864元，不等于真实账单。这是用户中转价，不是官方OpenAI价格。首次真实验收建议search-only与local，LLM付费验收另行确认。

## 排序

v2综合匹配度保持完全=1、部分=0.5、未匹配=0，必须项权重2、加分项1。新排序分：综合匹配度30%、必须技术完全覆盖10%、城市偏好25%、JD岗位质量20%、AI方向相关度10%、2027届明确适配5%。城市分广州100、上海45、深圳20，不从来源网站所在地推断工作地点。

先按广州有效去重候选数量判断是否足够，默认2（`--city-min`可配，受候选上限约束），不足补上海，再不足补深圳；足够就不访问下一阶段来源。`--guangzhou-only`禁止扩展。来源配置的`search_city`表示搜索阶段（广州/上海/深圳/不限），不是岗位城市。共享列表只访问一次。其他城市及未知地点不进核心候选。无效、重复、过期岗位不计足够数量。

JD质量证据分：AI工程职责35、可交付实践25、工程质量20、带教成长20。公司质量未有独立证据时保持待核验，不因宣传或公司名加分。方向相关度根据明确岗位标题：Agent/智能体100、LLM/RAG/大模型90、其他目标AI应用方向70。

默认城市顺序内按推荐等级、排序分排序。上海/深圳越级需综合≥80%、必须技术完全覆盖≥70%、无未匹配必须技能、质量≥75、方向≥90，原文JD、实习、明确面向2027届且无明确资格差距；还须比被越过的前序城市岗位综合匹配高≥20个百分点且排序分更高。报告记录越级资格、实际越过岗位与理由。不为了越级扩大真实搜索，未分析不生成分数。

广州高优先级沿用综合≥70%、必须覆盖≥60%、无未匹配必须技能、明确2027届原文实习条件；低城市高优先级须满足更严格的越级资格。综合<40%、必须项得分为0或明确资格差距仍标当前差距较大。分数不代表录用概率。

本轮修复编号/括号/Markdown章节导致加分项变必须项的问题；职责、学历/专业、福利和企业简介保持不同归属；HTML去掉导航与尾部信息。更新本地缓存规则版本，不复用旧错误报告，不删除历史。至少满足一项等语义组合仍保留原文供人工核对。
